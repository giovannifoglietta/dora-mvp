Critical Issues (fix before testing)

Critical AI calls are synchronous, but endpoints are async
classifier.py, extractor.py, and name_extractor.py all use the sync Anthropic client (anthropic.Anthropic) but are declared as async def functions. This means every AI call blocks the entire event loop — while one user's message is being classified, no other request can be served. Under any concurrency (even 2 simultaneous messages), the server will freeze.

Fix: Switch to anthropic.AsyncAnthropic and use await client.messages.create(...), or run the sync calls in a thread via asyncio.to_thread().
backend/ai/classifier.py:6-16 · extractor.py:6-17 · name_extractor.py:7-41
Critical No timezone handling — all datetimes are naive
The entire codebase uses naive datetimes (datetime.utcnow(), datetime.combine(d, t) without tzinfo). The DB schema uses TIMESTAMPTZ, so Supabase stores everything as UTC, but the Python code compares naive local times against UTC-stored times. This will cause bookings to be off by 1-2 hours (Italy is UTC+1/+2).

Fix: Use datetime.now(ZoneInfo("Europe/Rome")) everywhere. Make all datetime comparisons timezone-aware. The Practitioner.timezone field exists but is never used.
backend/logic/availability.py:37-38 · booking.py:25,84,124 · orchestrator.py:92
Critical No message logging — conversations are lost
The Message model exists in the schema, but nothing ever writes to it. The orchestrator processes messages and returns replies, but doesn't log either the inbound message or the outbound reply. This means: no conversation history for debugging, no data for prompt improvement, and no audit trail.

Fix: Add a log_message() call in the webhook handler or orchestrator, saving direction, body, intent, entities, and confidence for every exchange.
backend/webhooks.py:23-41 · orchestrator.py (no logging calls)

Warnings (should fix before go-live)

Warning 3 separate LLM calls per message — slow and expensive
Each user message triggers up to 3 serial Haiku calls: classify intent, extract entities, and (for new users) extract name. At ~0.5-1s each, that's 1.5-3s latency before the user gets a reply, plus 3x the API cost.

Suggestion: Combine classifier + extractor into a single call that returns both intent and entities in one JSON. The name extractor can stay separate since it only runs during onboarding.
backend/orchestrator.py:64-68
Warning Entity extractor doesn't know the day of week
The extractor prompt includes today's date but not the day of the week. When a user says "lunedi" the LLM has to calculate which date that is. Adding the weekday to the prompt would reduce extraction errors.

Fix: Add Oggi e: {weekday}, {today} to the EXTRACT_ENTITIES prompt.
backend/ai/prompts.py:15-25
Warning No confirmation step before booking
When a user provides both date and time, _handle_book() creates the booking immediately without asking "Ti prenoto per X alle Y — confermi?". This contradicts PIANO_MVP rule #1 ("Mai prenotare senza conferma") and could lead to accidental bookings.

Fix: Add a confirmation state: set pending_intent="confirm_book" with the proposed datetime, and only call create_booking() when the user says "si"/"confermo".
backend/orchestrator.py:159-192
Warning WhatsApp client is a stub
whatsapp.py just prints to console. For testing this is fine, but the plan calls for 360dialog integration by Week 3. The httpx import is unused.
backend/whatsapp.py:1-8
Warning No seed script — can't test without manual DB setup
There's no script to insert Silvia's practitioner record, working hours, and services into the database. Anyone cloning the repo can't test without manually writing SQL. The plan calls for a seed script.
Warning In-memory context won't survive restarts
ai/context.py stores conversation state in a Python dict. Every server restart (deploy, crash, Railway restart) wipes all in-flight conversations. A client mid-booking-flow will get a fresh state.

Acceptable for MVP if you're aware of it. For production, move to Redis or a DB table.
backend/ai/context.py
Warning No reminder system
The Booking model has reminder_sent but there's no scheduler or cron job to send 24h reminders. The plan puts this in Week 5. The files logic/packages.py and logic/reminders.py from the plan are not created yet.

Suggestions (nice to have)

Info Add error handling in webhook
If handle_message() throws an unhandled exception, the entire webhook returns a 500 and WhatsApp may retry, causing duplicate processing. Wrap in try/except, log the error, and return 200 so WhatsApp doesn't retry.
backend/webhooks.py:23-41
Info Deduplicate incoming messages
WhatsApp can deliver the same webhook payload multiple times. Without deduplication (checking message_id), a client could get double-booked. Store processed message IDs in a set or DB table.
Info The practitioner NLP instruct endpoint has no confirmation
"Cancella tutto domani" immediately cancels all bookings. There's no "Stai per cancellare 6 prenotazioni — confermi?" step. One typo by Silvia could wipe a full day.
backend/ai/practitioner_nlp.py:82-96
Info PIN auth is minimal
The practitioner login uses a hardcoded PIN stored in plain text in .env. Acceptable for MVP, but the cookie has no encryption and the PIN has no brute-force protection.
backend/practitioner.py:46-61
